# 키오스크 방문 도우미

상록원 1층 화면에 가상 발권·배식 시나리오를 제공한다. 2·3층에서는 키오스크 안내 준비 중 상태만 표시하고 분석 API를 요청하지 않는다. 실제 키오스크나 센서 측정값이 아니다. 기존 `/kiosk/ingest`와 `/congestion.kiosk`는 수신 호환용으로 유지하며 새 도우미는 해당 DB에 쓰거나 해당 값을 예측에 섞지 않는다.

화면은 식당 이용 현황·최근 발권량·방문 시간 힌트만 표시한다. 한식·일품·분식의 코너 카드와 수량·품절 전망 영역은 제거했다. 고정 시연의 내부 준비 수량 제한과 응답 필드는 호환성을 위해 유지한다.

## 실행과 시연

프로젝트 루트에서 `venv/Scripts/python.exe -m uvicorn server.main:app --host 0.0.0.0 --port 8000 --workers 1` 실행 후 `/dashboard/`에 접속한다. 기존 `CSI_FLOOR=2` 환경변수가 있다면 1로 변경하고 백엔드를 재시작한다. 초기 선택은 상록원 1층이며, 층 선택 버튼은 키오스크 위에 배치한다. 식단표는 기본적으로 접혀 있고 제목을 누르면 펼쳐진다.

상록원 1층 선택 시 제목 우측 `시연 시간` 버튼을 누르면 실시간 → 12:00 점심 피크 → 11:30 유입 시작 → 15:00 한산 → 실시간으로 전환한다. 실시간은 영업시간과 관계없이 연속된 목데이터를 보여주며 10초마다 갱신한다. 같은 10초 구간에서는 값이 같고, 새로고침·서버 재시작으로 과거 이력이 바뀌지 않는다. 현재 서울 시각은 응답 기준 시각으로 표시한다. 고정 시연은 날짜가 달라도 같은 발권 흐름을 재현한다. 새로고침·자동 갱신 정지와 연동되며, 일시정지 중에도 명시적인 모드 전환·수동 갱신은 실행한다. 다른 층에서는 버튼과 분석 내용을 숨기고, 다른 식당에서는 전체 키오스크 영역을 숨긴다.

## API

- FastAPI: `GET /kiosk/comprehensive-analysis`
- Vercel: `GET /api/kiosk-analysis`
- 선택 파라미터: `test_hour=0..23`, `test_minute=0..59`. 분은 시와 함께 지정하며, 시만 지정하면 정각이다.
- 오류: 잘못된 시각은 HTTP 422. 정상·오류 응답을 캐시하지 않는다.
- 프론트는 `/dashboard`에서는 같은 FastAPI origin, 배포 정적 화면에서는 같은 origin의 `/api/kiosk-analysis`를 호출한다. 별도 구성이 필요하면 `window.KIOSK_API_URL`을 `runtime-config.js`에 지정한다. CSI 주소인 `CONGESTION_API_BASE`와 독립적이다.
- 응답: `version`, `data_source: mock`, `location_id`, `floor`, `mode`, 서울 시간대가 포함된 `as_of`, `operating`, `summary_briefing`, `staying_estimation`, `surge_momentum`, `corners`, `golden_time_stats`.
- `mode`는 호환성을 위해 실시간 요청에서 `random`, 고정 시연 요청에서 `demo`다. 실시간의 `simulated_hour`는 현재 서울 시각의 시이고 `corners`는 빈 객체다. `as_of`는 응답 기준 시각이다.

## 계산 원칙

1. 실시간은 절대 시각의 10초 구간을 seed로 사용한다. 구간당 최대 1건, 30초마다 기본 1건에 완만하게 변하는 추가 발권을 더한다. 요청마다 새 시나리오를 뽑지 않는다. 최근 5분 발권량은 연속 갱신마다 최대 1건 변한다.
2. 가상 발권 30초 뒤 식사를 시작하고 20분 뒤 퇴장한다. 같은 발권 이력으로 현재 인원과 10분 내 퇴장을 계산한다. 10초 갱신 시 현재 인원 변화는 최대 1명이다. 최대 120명은 시연 가정이며 실제 식당 정원이나 AI 모델의 학습 기준을 바꾸지 않는다.
3. 최근 30분 그래프는 같은 발권 이력의 5분 구간 6개다. 시간이 5분 지나면 기존 구간은 그대로 이동한다. 평소 대비는 가상 기준 10분 40건이다. 현재 90명 이상이고 향후 10~45분에 10% 이상 감소하는 구간이 있을 때 방문 시간을 안내한다.
4. 고정 시연은 기존 1분 단위 수요·배식·체류 시나리오를 유지한다. 재고 한도 안에서 발권하며, 배식 후 10~40분 체류를 가정한다. 표시 인원은 120명 이하, 퇴장 예상은 현재 인원 이하로 제한한다. 평소 대비 기준은 12시 85건, 11·13·18시 50건, 나머지 운영시간 20건이다.
5. 발권 증감률은 최근 두 5분 구간을 비교한다. 직전 0건·현재 유입은 비율 `null`(새 유입), 두 구간 모두 0건은 0%다. 25% 이상이면 경보를 표시한다. 모든 수치는 가상 시연이며 실제 통계 또는 학습 모델 예측이 아니다.

공식 메뉴·운영시간은 기존 메뉴 영역이 담당한다. 가상 코너와 09:00~19:00 운영 설정은 실제 운영 안내가 아니다. CSI는 실제 측정 시각·출처를 별도로 표시하며, 가상 지표를 센서 검증 근거로 사용하지 않는다.

## 검증

`node tests/frontend_smoke.cjs`와 `venv/Scripts/python.exe -B -X utf8 -m unittest discover -s tests -v`를 실행한다. Python 의존성 설치 시 Windows에서는 `-X utf8` 사용을 권장한다. 기존 서버·테스트·전처리·AI requirements를 사용하며 이 기능 자체는 Python 표준 라이브러리만 필요하다.

발권·배식·재고 보존, 자정 전후 연속 갱신의 인원·발권 변화 상한, 120명 상한, 과거 구간 보존, 시연 시각, API 검증, 모드·층 변경 중 응답 경합, 2·3층 API 요청 억제, 코너 영역 제거, 식단 토글 상태 유지, 기존 센서·메뉴·식당 선택을 검증한다. Vercel 함수는 공통 분석 모듈만 가져오므로 AI 모델·DB를 배포할 필요가 없다.
