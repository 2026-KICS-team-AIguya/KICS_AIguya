# 키오스크 방문 도우미

상록원 2층 화면에 가상 발권·배식·재고 시나리오를 제공한다. 실제 키오스크나 센서 측정값이 아니다. 기존 단순 발권 패널은 새 도우미로 교체했고, 기존 `/kiosk/ingest`와 `/congestion.kiosk`는 이전 수신기와의 호환을 위해 유지한다. 새 도우미는 해당 DB에 쓰거나 해당 값을 예측에 섞지 않는다.

## 실행과 시연

프로젝트 루트에서 `.venv/Scripts/python.exe -m uvicorn server.main:app --host 127.0.0.1 --port 8000` 실행 후 `/dashboard/`에 접속한다. 팀 내 공유기 시연은 기존 안내처럼 `--host 0.0.0.0`을 사용한다.

선택 식당 제목 우측 `시연 시간` 버튼을 누를 때마다 실시간 → 12:00 점심 피크 → 11:30 유입 시작 → 15:00 한산 → 실시간으로 전환한다. 실시간도 현재 서울 시각 기준의 가상 데이터다. 고정 시연은 날짜가 달라도 같은 발권 흐름을 재현한다. 새로고침·자동 갱신 정지와 연동되며, 일시정지 중에도 명시적인 모드 전환·수동 갱신은 실행한다. 다른 식당에서는 표시하지 않는다.

## API

- FastAPI: `GET /kiosk/comprehensive-analysis`
- Vercel: `GET /api/kiosk-analysis`
- 선택 파라미터: `test_hour=0..23`, `test_minute=0..59`. 분은 시와 함께 지정하며, 시만 지정하면 정각이다.
- 오류: 잘못된 시각은 HTTP 422. 정상·오류 응답을 캐시하지 않는다.
- 프론트는 `/dashboard`에서는 같은 FastAPI origin, 배포 정적 화면에서는 같은 origin의 `/api/kiosk-analysis`를 호출한다. 별도 구성이 필요하면 `window.KIOSK_API_URL`을 `runtime-config.js`에 지정한다. CSI 주소인 `CONGESTION_API_BASE`와 독립적이다.
- 응답: `version`, `data_source: mock`, `location_id`, `floor`, `mode`, 서울 시간대가 포함된 `as_of`, `operating`, `summary_briefing`, `staying_estimation`, `surge_momentum`, `corners`, `golden_time_stats`.

## 계산 원칙

1. 하루 1분 단위 수요와 ±15% 변동으로 발권을 생성한다. 날짜·코너·분에 따른 결정적 난수로 이전 이력이 유지된다. 재고를 넘겨 발권하지 않는다.
2. 대기열은 이전 미처리량 + 새 발권 - 배식량을 누적한다. 분당 배식량은 한식 5명, 일품 2명, 분식 3명이다. `backlog / service_rate`는 현재 처리 속도 기준의 추가 방문자 예상 대기다.
3. 배식을 완료한 사람에 한해 체류를 추정한다. 10분까지 잔류 확률 1, 40분까지 선형 감소한다. 퇴장은 현재와 10분 뒤 생존 확률의 차이로 계산하며, 좌석 공석 수와 동일하지 않다.
4. 발권 가속도는 최근 두 5분 구간을 비교한다. 직전 0건·현재 유입은 비율 `null`(새 유입), 두 구간 모두 0건은 0%다. 25% 이상이면 경보를 표시한다.
5. 남은 재고 / 최근 15분 분당 발권량으로 품절 시점을 추정한다. 소진 속도가 없거나 가상 영업 종료 이후면 예측하지 않는다. UI는 60분 이내 전망을 표시하고 20분 이내면 강조한다. 재고 0은 별도의 품절 상태다.
6. 평소 대비 기준은 시연용 고정값(12시 85건, 11·13·18시 50건, 나머지 운영시간 20건)이다. 운영시간 밖은 비교하지 않는다. 추천 시간은 향후 10~45분의 가상 대기열과 판매 가능한 코너를 비교해 평균 대기가 충분히 감소할 때만 제공한다. 실제 통계 또는 학습 모델 예측이 아니다.

공식 메뉴·운영시간은 기존 메뉴 영역이 담당한다. 가상 코너와 09:00~19:00 운영 설정은 실제 운영 안내가 아니다. CSI는 실제 측정 시각·출처를 별도로 표시하며, 가상 지표를 센서 검증 근거로 사용하지 않는다.

## 검증

`node tests/frontend_smoke.cjs`와 `.venv/Scripts/python.exe -B -X utf8 -m unittest discover -s tests -v`를 실행한다. Python 의존성 설치 시 Windows에서는 `-X utf8` 사용을 권장한다. 기존 서버·테스트·전처리·AI requirements를 사용하며 이 기능 자체는 Python 표준 라이브러리만 필요하다.

발권·배식·재고 보존, 구간 연속성, 퇴장 인원 상한, 시연 시각, API 검증, 모드 변경 중 응답 경합, 오류와 복구, 기존 센서·메뉴·식당 선택을 검증한다. Vercel 함수는 공통 분석 모듈만 가져오므로 AI 모델·DB를 배포할 필요가 없다.
