## 2. 프로젝트가 하는 일

카메라·영상 없이 **무선 신호의 변화**만으로 공간의 혼잡도를 판정하고 예상 대기시간을 알려준다.

```
ESP32 Wi-Fi CSI  → 동적 움직임 감지 (사람이 오가는 정도)
mmWave 레이더    → 정적 좌석 점유 감지 (앉아 있는 사람)
키오스크 발권량   → 유입 수요
        ↓
   5초 단위 정렬 → 5분 슬롯 집계
        ↓
   AI 모델 (혼잡도 분류 + 대기시간 예측)
        ↓
   웹 대시보드 (구역별 혼잡도 실시간 표시)
```

**두 센서를 쓰는 이유**: mmWave는 앉아 있는 사람은 잘 잡지만 "지금 붐비는 중인지"는 모른다.
CSI는 움직임을 잡지만 위치를 모른다. 둘을 합쳐야 "찼는데 조용함(안정)"과 "찼고 유입 중(더 붐빌 예정)"이 구분된다.

## 4. 하드웨어

| 장비 | 모델 | 현황 |
|------|------|------|
| Wi-Fi CSI | ESP32 DevKit (USB-C) | **2대 보유** (TX 1 + RX 1) |
| mmWave | HLK-LD6001A (60GHz) | 주문 예정 ⚠️ 리드타임 |

**ESP32 CSI 수집 구조**
```
RX ─ 핫스팟 연결
   ─ promiscuous(sniffer) 활성화   ← station 모드만으론 CSI 샘플 부족
   ─ TX MAC 필터링                 ← 주변 패킷이 다 날아다님
   ─ CSI 추출 → Wi-Fi로 Mac 전송
```
⚠️ 무선 전송 자체가 채널을 점유해 CSI 수집에 영향 → raw 전부보다 feature만 전송 권장

**팀원 장비**
| 팀원 | 장비 |
|------|------|
| 희수 | Mac M5 Air |
| 진호 | LG gram (RTX3050) + GTX1080 데스크탑 |
| 송주 | 리눅스 노트북 + i5-14600K/RTX5060 데스크탑 |
| 채은 | RTX3070 데스크탑 (학습 허브) |

## 5. 데이터 규격 ★ 가장 중요

### 시간

| 항목 | 값 |
|------|-----|
| 타임스탬프 | epoch **milliseconds 정수** |
| 공통 시각 기준 | **`host_epoch_ms`** (호스트가 찍은 시각) |
| Raw | **원본 그대로. 반올림 금지** |
| Feature | **5초 grid** |
| 경계 규칙 | window **시작 시각**, `[start, end)` |
| 집계 단위 | 5분 (송주가 처리) |
| feature window | **센서 담당자 재량** (실험 후 결정) |

```
RAW                              FEATURE
1785397655123                    timestamp = 1785397655000
1785397655134    ──신호처리──→    → [1785397655000, 1785397660000)
1785397655144                    csi_amp_var = 0.31
```

> **Raw에는 `device_time_us`와 `host_epoch_ms` 둘 다 남길 것** (버퍼링 지연 확인용)

### 식별자

| 소스 | 식별자 |
|------|--------|
| mmWave | `zone` (zone_A / zone_B / zone_C) |
| CSI | **`link_id`** (link_A ...) + 배치 확정 시 `zone` 매핑 |
| 외부 | 없음 (timestamp만) |

> **`link_id`와 `zone`은 다르다.**
> 물리적 실체는 `TX ↔ RX_A = link_A`이고,
> "link_A를 zone_A 근처에 배치했다"는 것은 우리의 실험 설계다.
> ESP32가 zone을 인식하는 게 아니다.

### 파일

| 항목 | 값 |
|------|-----|
| 접두사 | `csi_` / `mm_` / `ext_` |
| 결측 | **빈칸** — `-1` 금지 |
| 파일명 | `{소스}_{YYYYMMDD}_{HHMM}.csv` |
| raw 보관 | **필수** (feature와 별도) |

**특징값 목록은 자유.** 접두사와 필수 컬럼만 지키면 각자 결정.
단, 컬럼을 추가·변경하면 송주에게 알릴 것.

### 결측률 컬럼 (필수)

> **CSI는 패킷이 안 오면 행 자체가 안 생긴다.** ESP32 CSI callback은 수신될 때만 호출되므로 빈칸으로 결측을 판단할 수 없다.

```
CSI  : csi_packet_count, csi_missing_rate
mmWave: mm_frame_count
```

### 파일 예시

```csv
# csi_20260810_1800.csv
timestamp,link_id,zone,csi_amp_var,csi_amp_mean,csi_packet_count,csi_missing_rate
1785397655000,link_A,,0.31,12.4,493,0.014

# mm_20260810_1800.csv
timestamp,zone,mm_presence,mm_static_energy,mm_moving_energy,mm_frame_count
1785397655000,zone_A,1,0.91,0.12,98

# label_20260810_1800.csv
start_timestamp,end_timestamp,zone,seats,occupied,status,level
1785397500000,1785397800000,zone_A,10,7,앉음,혼잡
```

### 라벨

| 항목 | 값 |
|------|-----|
| 기록 주기 | 5분 |
| 현장 기록 | `12:05~12:10` (종이) |
| CSV 저장 | epoch ms 변환 |
| 누가 | 4명 공동 |

**혼잡 등급 (점유율 기준, 경계 중복 없음)**
```
여유 : ≤ 30%
보통 : 30% < x < 70%
혼잡 : ≥ 70%
```

> 인원수가 아니라 점유율인 이유: 구역마다 좌석 수가 다르고, 다른 공간으로 확장해도 그대로 쓸 수 있다.
> 구역별 좌석·인원을 적으면 **전체 혼잡도도 자동 계산**된다 (CSI 단독 모델 학습용).

### 동기화

| | 역할 |
|---|---|
| NTP | **주 동기화 수단** |
| 손 흔들기 | **검증·보정용 백업** |

**어디서 흔드나**: CSI는 TX-RX 사이 전파 경로를 가로막도록, mmWave는 레이더 시야 안에.
→ **두 조건을 동시에 만족하는 위치**에서. 세션 시작·끝 각 5초, 라벨 표에 시각 기록.

## 6. 진행 단계

```
1단계  규격 확정 (회의)              ← 현재 위치
2단계  각자 준비 (센서 세팅 / 서버 뼈대)
3단계  데이터 수집 + 라벨링          ← 가장 오래 걸리고 가장 중요
4단계  학습 데이터셋 생성 (송주)
5단계  AI 모델 학습
6단계  모델을 서버에 탑재 + 시연
```

**중요한 구분**
- **수집(3단계)에는 서버가 필요 없다.** 각자 노트북에 CSV로 저장 → 파일로 전달
- **서버는 시연용.** 송주는 더미 데이터로 미리 만들어둠 (센서 안 기다림)
- **AI는 별도 단계가 아니라 서버의 한 칸.** 처음엔 `if`문, 나중에 `model.predict()`로 교체

## 7. 모델 구성

| 모델 | 담당 | 용도 |
|------|------|------|
| CSI 단독 | 희수 | 실험 — CSI만으로 전체 혼잡도 얼마나 맞히나 |
| mmWave 단독 | 진호 | 실험 — mmWave만으로 구역별 점유 얼마나 맞히나 |
| **융합** | 송주+채은 | **실제 서비스 탑재** |

**ablation 필수**: CSI 넣고/빼고 성능 차이를 수치로 제시해야 "왜 센서 두 개를 썼나"에 답할 수 있다.

**학습 데이터 형태**
```
timestamp      zone     mm_static  mm_moving  csi_var  level
...655000      zone_A   0.91       0.12       0.31     혼잡
...655000      zone_B   0.05       0.02       0.31     여유   ← csi는 전체값이라 동일
```

**주의**
- 스케일러는 **train에만 fit**하고 파일로 저장 → 서버에서 로드만 (새로 fit 금지)
- CSI 결측을 앞값으로 채우지 말 것 (값의 변화가 곧 움직임 신호 → "안 움직였다"는 가짜 신호가 됨). 짧은 것만 보간, 긴 것은 제외
- 전처리는 **함수 단위로** 작성 → 학습·서버 양쪽에서 재사용 (두 번 짜면 어긋나서 성능 하락)

## 8. 기술 스택

```
서버    : FastAPI (Django 아님)
DB      : SQLite
전처리  : pandas
학습    : scikit-learn (RandomForest 계열)
프론트  : HTML + Chart.js
CSI 펌웨어: ESP-IDF (C)
```

**FastAPI를 쓰는 이유**: 자동 API 문서(`/docs`)로 팀원이 "어디로 뭘 보내는지" 바로 확인 가능,
타입 힌트로 규격 위반 자동 검증, 가볍고 배울 게 적음.
Django의 관리자 페이지·인증·템플릿은 우리가 안 쓴다.

├─ server/            # 송주 — FastAPI

> 공용 함수로 빼두면 `server/`에서 `from pipeline.align import ...`로 가져다 쓸 수 있고,
> 같은 로직을 두 번 짜서 어긋나는 사고를 막는다.

## 11. 아직 정해지지 않은 것 ⚠️

> **이 항목들은 회의에서 결론이 나면 이 파일을 갱신할 것.**

- [ ] **수집 장소** → ______ / **서비스 대상 공간** → ______ / 같은 곳인가?
  - 다르면 CSI 신호 패턴이 달라 실제로도 안 맞고 심사에서 지적당함
  - "파일럿 검증용"이라고 선을 긋든지, 대상을 일치시키든지 결정 필요
- [ ] **CSI 범위**: 전체 공간(선택 A, 추천) vs 구역별(선택 B, RX 2대 추가)
- [ ] **정렬 단위**: 5초 (진호 프레임 주기 확인 후 / 5Hz 미만이면 10초)
- [ ] **구역 개수**: 3개 (진호 zone 지원 개수 확인 후)
- [ ] **구역별 좌석 수** (점유율 계산에 필수)
- [ ] **대기시간**: 실측 vs 휴리스틱
  - 실측 안 하면 학습 불가 → "휴리스틱 추정"이라고 정직하게 명시해야 함
  - "대기시간 뭘로 검증했나요?"가 심사 최대 위험 질문
- [ ] **채은 외부 데이터 용도**
  - AI Hub 등 과거 데이터셋은 시각이 안 맞아 학습 데이터에 병합 불가 → 참조용
  - 실제 feature가 되는 건 날씨·학사일정·요일 등 시각이 맞는 데이터

## 12. 심사 방어 포인트

| 취약점 | 대응 |
|--------|------|
| "ISAC" 표현 | 엄밀히는 CSI 기반 전파 센싱. 톤 다운 |

| 정확도 KPI | 라벨 표본 수 밝히고 "예비 결과"로 프레이밍 |
| mmWave 기여 | **ablation 델타 제시 필수** |
| mmWave 정적 감지 | 카운팅 대신 점유/비점유로 낮춘 것 자체가 방어 |
| CSI 환경 드리프트 | 가구·군중 바뀌면 모델이 깨짐 → 재보정 언급 |
| 프라이버시 | "완전 안전"은 과장. "영상 미수집으로 초상권 부담 경감" |
| 수집 장소 불일치 | 서비스 대상과 다르면 반드시 선 긋기 |

## 13. AI 툴 활용 시 참고

이 파일을 첨부하고 아래처럼 요청하면 맥락이 이어진다.

**전처리 코드:**
```
"README 5번 규격을 참고해서 csi/mm/label CSV를 병합하고
5분 슬롯으로 집계하는 함수를 pandas로 작성해줘."
```

**서버:**
```
"README 8번 스택으로 FastAPI 수신 API를 만들어줘.
5번 규격의 컬럼을 pydantic으로 검증하고 SQLite에 저장."
```

**신호처리:**
```
"README 5번 규격에 맞게 CSI 특징값을 5초 grid로 출력하는 코드를 작성해줘.
csi_packet_count와 csi_missing_rate도 포함."
```

**주의사항 (AI에게 반드시 전달)**
- Raw timestamp는 반올림 금지, feature만 5초 grid
- window 경계는 `[start, end)`, 시작 시각 기준
- 결측은 빈칸, `-1` 금지
- CSI 결측을 앞값으로 채우지 말 것
- 스케일러는 train에만 fit하고 저장 → 서버에서는 로드만
- 전처리는 함수 단위로 (학습·서버 양쪽 재사용)
- 데이터 파일은 git에 커밋하지 말 것
